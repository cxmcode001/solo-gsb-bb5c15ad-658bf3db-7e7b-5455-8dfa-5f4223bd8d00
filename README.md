# 无线麦克风频率协调工具

面向现场音频工程师的无线麦克风频率协调 Web 应用。录入设备频率后自动分析互调冲突，并在指定约束下自动协调出无冲突、总偏移最小的频率方案，支持方案保存与回放。

## 功能

- **设备管理**：录入最多 8 个设备（名称、工作频率 MHz、保护间隔 MHz），可锁定频道、编辑、删除
- **互调冲突分析**：对任意两个不同频道枚举 `|f1−f2|`、`f1+f2`、`|2f1−f2|`（含两种有序组合），标出落入任一频道保护区（载频 ± 保护间隔，含边界）的互调积，并显示来源频道对与受影响频道
- **自动频率协调**：在指定频段、步进、最大偏移内调整未锁定频道（锁定频道保持不动），通过回溯搜索找出**总偏移最小**的无冲突方案；总偏移相同时按录入顺序选择更低频率；无解时保持原值并说明原因
- **方案管理**：保存协调方案、查看详情、一键应用回设备、删除
- **持久化**：SQLite 存储设备与方案，容器重启不丢失

## 快速开始（Docker，单条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:3000**

> 数据库首次启动时自动初始化（`CREATE TABLE IF NOT EXISTS`），无需额外迁移步骤。
> SQLite 数据文件存放在命名卷 `app-data` 中；停止容器可用 `docker compose down`。

## 本地开发（不用 Docker）

```bash
npm install
npm start          # 启动服务，默认 3000 端口
npm run dev        # 开发模式（文件变更自动重启）
npm test           # 运行核心算法测试（node:test）
```

访问 http://localhost:3000 。数据默认写入 `./data/coordinator.db`，可用环境变量 `DATA_DIR`、`PORT` 覆盖。

## 使用说明

1. **录入设备**：在「设备列表」中填写名称、频率（如 `512.000`）、保护间隔（默认 `0.25` MHz），可勾选锁定。也可点击「载入示例」快速填充 8 通道示例数据。
2. **查看冲突**：冲突分析随设备变更自动刷新，表格列出互调类型、互调积频率、来源频道、受影响频道及偏差。
3. **自动协调**：设置频段上下限、步进（如 `0.025` MHz = 25 kHz）、最大偏移，点击「开始协调」。成功后可将结果「应用到设备」或「保存方案」。
4. **方案回放**：在「已保存方案」中查看历史方案，可一键应用或删除。

## 协调算法

- 每个未锁定频道的候选频率为 `原频 ± k × 步进`（`k × 步进 ≤ 最大偏移`），且必须落在指定频段内
- 搜索目标：所有频道总偏移 `Σ|新频 − 原频|` 最小；同分时按录入顺序逐频道比较，取更低频率
- 采用带回溯的分支限界搜索，随频道逐个确定增量检查互调积；设节点上限（200 万）防止极端参数下搜索爆炸，触顶时返回当前最优并明确标注
- 无解时所有频道保持原值，并返回可读的原因说明

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/devices` | 设备列表 |
| POST | `/api/devices` | 新增设备（最多 8 个） |
| PUT | `/api/devices/:id` | 更新设备 |
| DELETE | `/api/devices/:id` | 删除设备 |
| GET | `/api/conflicts` | 当前配置的互调冲突列表 |
| POST | `/api/coordinate` | 自动协调（body：`bandMin/bandMax/step/maxOffset`，单位 MHz） |
| GET / POST | `/api/plans` | 方案列表 / 保存方案 |
| DELETE | `/api/plans/:id` | 删除方案 |
| POST | `/api/plans/:id/apply` | 将方案频率应用回设备 |
| POST | `/api/seed` | 空库时载入示例数据 |

## 技术栈

Node.js 20 · Express 4 · better-sqlite3（WAL 模式）· 原生 HTML/CSS/JS（无前端框架）

```
├── server.js            # Express 服务与 API 路由
├── db.js                # SQLite 连接与建表
├── lib/intermod.js      # 互调计算与自动协调核心（纯函数，可独立测试）
├── public/              # 前端页面（index.html / app.js / style.css）
├── test/                # 核心算法测试（node:test）
├── Dockerfile
└── docker-compose.yml
```
